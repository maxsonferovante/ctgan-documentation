1. Visão Geral da Dependência

O CTGAN depende do RDT (Reversible Data Transforms) para converter colunas tabulares brutas em representações numéricas adequadas para redes neurais. Essa conversão é feita pelo DataTransformer do CTGAN, que orquestra transformadores do RDT para cada coluna do dataset.

Dependência Circular

O CTGAN importa apenas 2 classes do RDT. Porém, essas classes trazem uma cadeia de herança de 3 níveis com funcionalidades substanciais que o CTGM受益 indiretamente.

2. Classes RDT Utilizadas

Classe Módulo Uso no CTGAN Linhas de Código
ClusterBasedNormalizer rdt.transformers.numerical Colunas contínuas — normalização com Bayesian GMM ~190
OneHotEncoder rdt.transformers.categorical Colunas discretas — codificação one-hot ~145

A importação original no CTGAN:

from rdt.transformers import ClusterBasedNormalizer, OneHotEncoder

3. Cadeia de Herança

Cada classe do RDT que o CTGM usa herda funcionalidade de 2 classes base:

BaseTransformer → FloatFormatter → ClusterBasedNormalizer
BaseTransformer → OneHotEncoder

3.1 BaseTransformer (606 linhas)

Classe base para todos os transformadores do RDT. Fornece:

Usado pelo CTGAN
  • fit(data, column_name) — API pública de ajuste
  • transform(data) — API pública de transformação
  • reverse_transform(data) — API pública de reversão
  • get_output_sdtypes() — metadados das colunas de saída
  • dummies — categorias encontradas (OneHotEncoder)
NÃO usado pelo CTGAN
  • random_states — gerenciamento de estado aleatório por método
  • set_random_state() — controle de reprodutibilidade
  • reset_randomization() — resetar estado
  • output_properties — metadados de propriedades de saída
  • set_fitted_parameters() — ajuste manual
  • is_generator() — verificar se gera dados
  • get_name() — nome da classe
  • get_subclasses() — subclasses disponíveis

3.2 FloatFormatter (888 linhas)

Transformador para dados numéricos. Herda de BaseTransformer. Fornece:

Usado pelo CTGAN (indiretamente)
  • missing_value_generation='from_column' — tratamento de nulos
  • NullTransformer — substituição de valores nulos
  • _dtype — preservação do tipo original
NÃO usado pelo CTGAN
  • learn_rounding_scheme — preservar casas decimais
  • enforce_min_max_values — clip nos valores originais
  • computer_representation — Int8/16/32/64, UInt, Float
  • missing_value_replacement — estratégia de substituição (mean/mode/random)
  • _rounding_digits — dígitos de arredondamento aprendidos
  • _min_value / _max_value — limites originais

3.3 ClusterBasedNormalizer

Herda de FloatFormatter. Implementação específica do CTGAN:

Usado pelo CTGAN
  • max_clusters — número máximo de componentes GMM
  • weight_threshold — limiar de peso para componentes válidos
  • valid_component_indicator — quais componentes são válidos
  • STD_MULTIPLIER = 4 — multiplicador de desvio padrão
  • fit(data, column_name)
  • transform(data)
  • reverse_transform(data)
  • get_output_sdtypes()

3.4 OneHotEncoder

Herda de BaseTransformer (não de FloatFormatter):

Usado pelo CTGAN
  • dummies — lista de categorias encontradas
  • fit(data, column_name)
  • transform(data)
  • reverse_transform(data)
  • get_output_sdtypes()
NÃO usado pelo CTGAN
  • _dummy_na — tratamento de nulos como categoria
  • _dummy_encoded — codificação por índice
  • _indexer — mapeamento de índices
  • output_properties — propriedades de saída

4. Métodos Chamados pelo CTGAN

Todos os métodos são chamados através do DataTransformer do CTGAN:

4.1 ClusterBasedNormalizer

Método Chamado em Parâmetros Retorna
fit DataTransformer._fit_continuous() data (pd.DataFrame), column_name (str) None (ajusta o modelo internamente)
transform DataTransformer._transform_continuous() data (pd.DataFrame com 1 coluna) pd.DataFrame com colunas .normalized e .component
reverse_transform DataTransformer._inverse_transform_continuous() data (pd.DataFrame com colunas do get_output_sdtypes()) pd.DataFrame com 1 coluna (valores originais)
get_output_sdtypes DataTransformer._inverse_transform_continuous() Nenhum dict com nomes das colunas de saída
valid_component_indicator DataTransformer._fit_continuous() — np.array booleano indicando componentes válidos

4.2 OneHotEncoder

Método Chamado em Parâmetros Retorna
fit DataTransformer._fit_discrete() data (pd.DataFrame), column_name (str) None (ajusta internamente)
transform DataTransformer._transform_discrete() e convert_column_name_value_to_id() data (pd.DataFrame com 1 coluna) pd.DataFrame com N colunas one-hot
reverse_transform DataTransformer._inverse_transform_discrete() data (pd.DataFrame com colunas do get_output_sdtypes()) pd.DataFrame com 1 coluna (categorias originais)
get_output_sdtypes DataTransformer._inverse_transform_discrete() Nenhum dict com nomes das colunas de saída
dummies DataTransformer._fit_discrete() — lista de categorias encontradas

5. Fluxo de Dados: CTGAN ↔ RDT

5.1 Pipeline de Fit (Treinamento)

// CTGAN.fit() inicia o processo train_data = pd.DataFrame // dados brutos do usuário // Para cada coluna contínua: ClusterBasedNormalizer.fit(data, column_name) └─ Herda de FloatFormatter._fit() ├─ _validate_values_within_bounds() // valida limites ├─ preserva self._dtype // tipo original ├─ aprende self._rounding_digits // se learn_rounding_scheme=True ├─ aprende self._min_value, self._max_value // se enforce_min_max_values=True └─ cria NullTransformer // trata nulos └─ substitui nulos por mean (ou random/from_column) └─ ClusterBasedNormalizer._fit() ├─ ajusta BayesianGaussianMixture com sklearn └─ define valid_component_indicator // Para cada coluna discreta: OneHotEncoder.fit(data, column_name) └─ Herda de BaseTransformer.fit() └─ OneHotEncoder._fit() ├─ descobre categorias únicas ├─ define self.dummies └─ define self.output_properties

5.2 Pipeline de Transform (Geração)

// CTGAN gera dados sintéticos → precisa reverter para formato original // Para colunas contínuas: ClusterBasedNormalizer.transform(data) └─ FloatFormatter._transform() └─ NullTransformer.transform() // já tratou nulos no fit └─ ClusterBasedNormalizer._transform() ├─ normaliza: (x - mean) / (4 * std) ├─ seleciona componente via predict_proba └─ retorna: [.normalized, .component] // Para colunas discretas: OneHotEncoder.transform(data) └─ BaseTransformer.transform() └─ OneHotEncoder._transform() └─ retorna: [cat_a, cat_b, cat_c, ...] // 0 ou 1

5.3 Pipeline de Reverse Transform (Desfazer)

// CTGAN converte dados sintéticos de volta ao formato original // Para colunas contínuas: ClusterBasedNormalizer.reverse_transform(data) └─ ClusterBasedNormalizer._reverse_transform_helper() ├─ extrai componente selecionado ├─ recupera mean e std do componente └─ reversão: x = normalized * 4 * std + mean └─ FloatFormatter._reverse_transform() ├─ aplica clip(min, max) // se enforce_min_max_values=True ├─ aplica round(digits) // se learn_rounding_scheme=True ├─ converte para self._dtype // tipo original └─ reverte nulos via NullTransformer // Para colunas discretas: OneHotEncoder.reverse_transform(data) └─ BaseTransformer.reverse_transform() └─ OneHotEncoder._reverse_transform() ├─ argmax(one_hot) // encontra índice da categoria └─ mapeia índice → self.dummies[índice]

6. O que o CTGAN Realmente Usa

Resumo: Interface mínima necessária

O CTGM usa apenas 5 métodos/propriedades por transformador:

Classe Métodos/Propriedades
ClusterBasedNormalizer fit(data, column_name), transform(data), reverse_transform(data), get_output_sdtypes(), valid_component_indicator
OneHotEncoder fit(data, column_name), transform(data), reverse_transform(data), get_output_sdtypes(), dummies

7. O que Descartamos na Reimplementação

Funcionalidades perdidas

Nossa reimplementação em data_transformer.py ignora:

De FloatFormatter:

  • Tratamento de nulos: NullTransformer com estratégias mean/random/from_column —我们的实现假设 dados limpos
  • Arredondamento: learn_rounding_scheme — não preserva casas decimais
  • Limites: enforce_min_max_values — não faz clip nos valores
  • Representação: computer_representation — não suporta Int8/16/32/64
  • Tipo original: _dtype — não restaura tipo da coluna

De BaseTransformer:

  • Reprodutibilidade: sistema de random_states por método
  • Metadados: output_properties e pipeline de transformadores
  • Validação: validação de input/output
  • API genérica: fit_transform(), set_fitted_parameters()
Impacto no CTGAN

Para o uso específico do CTGAN, a maioria dessas funcionalidades não é crítica:

  • O CTGAN já valida nulos antes de chamar o RDT (_validate_null_data())
  • O CTGAN trabalha com float64 internamente — arredondamento e representação não importam
  • O clip e dtype restoration são importantes para qualidade dos dados sintéticos, mas não para treinamento

Porém, se o RDT for usado por outros algoritmos de geração (Gaussian Copula, etc.), essas funcionalidades são importantes.

8. Decisão: Forcar o RDT

Por que forcar é melhor que reimplementar
  • Completude: herda toda a lógica de null handling, rounding, min/max, tipos
  • Reutilizabilidade: outros algoritmos de geração podem usar o mesmo RDT Polars
  • Manutenibilidade: quando o RDT lançar novas features, podemos merge
  • Menos código: não precisamos reimplementar o que já existe
