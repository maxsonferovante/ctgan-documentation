1. Por que normalizar? O problema fundamental

Redes neurais e GANs trabalham exclusivamente com números contínuos. Um dataset bancário típico contém:

TipoExemploProblema
Contínuobalance = 12450.00Range enorme (−500 a +500.000), distribuição assimétrica
Categóricostatus = "Active"String — o modelo não sabe o que é "Active"
Booleanois_premium = TruePode ser 0/1, mas precisa de tratamento consistente
Datetime2024-01-15 08:30:00Timestamp — precisa virar número
NuloNaNGANs não lidam com valores ausentes

O RDT (Reversible Data Transforms) resolve isso com uma propriedade crucial: reversibilidade. Dado um dado x:

Propriedade de reversibilidade
x → encode(x) → x_codificado → GAN → x_sintético_codificado → decode(x_sintético) → x_sintético

Queremos: x_sintético ≈ x com perda mínima de informação

Regra de ouro: O RDT converte tudo para float64 em ranges como [-1, 1], [0, 1] ou N(0,1) — formats que a rede neural consegue aprender.

3. FloatFormatter — A base numérica

O FloatFormatter é o transformador base para todos os dados numéricos. Ele não faz normalização profunda — apenas garante que os dados são float64 e aplica arredondamento.

5. ClusterBasedNormalizer — GMM Bayesiano + normalização 4σ

Este é o transformador principal usado pelo CTGAN para colunas contínuas. Em vez de normalizar a coluna inteira com um único z-score (que falha em distribuições multimodais), ele agrupa os dados em modos e normaliza cada modo separadamente.

Intuição: Se uma coluna balance tem dois picos (overdraft negativo e saldo alto positivo), um z-score simples colocaria todos no mesmo range, destruindo a separação entre os dois grupos. O ClusterBasedNormalizer mantém cada grupo com sua própria normalização.

1 _fit() — Ajuste do BayesianGMM ▸ 
# numerical.py:560-585
def _fit(self, data):
    sm = import_module('sklearn.mixture')

    self._bgm_transformer = sm.BayesianGaussianMixture(
        n_components=self.max_clusters,              # 10 (padrão)
        weight_concentration_prior_type='dirichlet_process',
        weight_concentration_prior=0.001,            # prior Dirichlet — favorece poucos modos
        random_state=self._get_current_random_seed(),
    )

    super()._fit(data)                                # FloatFormatter._fit
    data = super()._transform(data)                   # garante float64
    if data.ndim > 1:
        data = data[:, 0]

    self._bgm_transformer.fit(data.reshape(-1, 1))   # ajusta GMM na coluna

    # Poda: remove modos com peso < 0.5%
    self.valid_component_indicator = (
        self._bgm_transformer.weights_ > self.weight_threshold
    )

O que o BayesianGaussianMixture faz matematicamente

O BayesianGaussianMixture do sklearn implementa um GMM com inferência variacional. Diferente do GMM padrão (EM puro), ele usa:

Modelo de Mistura Gaussiana Bayesiano

1. Prior de Dirichlet nos pesos:
π₁, π₂, ..., πₖ ~ Dir(α₁, α₂, ..., αₖ)
onde α₁ = α₂ = ... = αₖ = 0.001 (concentração baixa = poucos modos)

2. Likelihood (cada componente):
P(x | componente=k) = N(x; μₖ, σₖ²)
onde N é a distribuição normal univariada

3. Posterior (Responsabilidades):
r(i,k) = P(componente=k | xᵢ) = [πₖ × N(xᵢ; μₖ, σₖ²)] / Σⱼ [πⱼ × N(xᵢ; μⱼ, σⱼ²)]

4. Atualização (M-step):
Nₖ = Σᵢ r(i,k) (tamanho efetivo)
μₖ = (1/Nₖ) × Σᵢ r(i,k) × xᵢ (média ponderada)
σₖ² = (1/Nₖ) × Σᵢ r(i,k) × (xᵢ - μₖ)² (variância ponderada)
πₖ = Nₖ / N (peso do modo)

2 _transform() — Normalização + Seleção de Modo ▸ 
# numerical.py:587-635
def _transform(self, data):
    data = super()._transform(data)          # lida com nulos via NullTransformer
    if data.ndim > 1:
        data, model_missing_values = data[:, 0], data[:, 1]

    data = data.reshape((len(data), 1))

    # Extrai parâmetros dos modos VÁLIDOS
    means = self._bgm_transformer.means_.reshape((1, self.max_clusters))
    means = means[:, self.valid_component_indicator]
    stds = np.sqrt(self._bgm_transformer.covariances_).reshape((1, self.max_clusters))
    stds = stds[:, self.valid_component_indicator]

    # PASSO A: Normalização pelo modo correspondente
    normalized_values = (data - means) / (self.STD_MULTIPLIER * stds)
    # STD_MULTIPLIER = 4, então: α = (x - μₖ) / (4 × σₖ)

    # PASSO B: Calcula probabilidade de cada modo para cada linha
    component_probs = self._bgm_transformer.predict_proba(data)
    component_probs = component_probs[:, self.valid_component_indicator]

    # PASSO C: Amostra um modo para cada linha (NÃO é argmax!)
    selected_component = np.zeros(len(data), dtype='int')
    for i in range(len(data)):
        component_prob_t = component_probs[i] + 1e-6
        component_prob_t = component_prob_t / component_prob_t.sum()
        selected_component[i] = np.random.choice(
            np.arange(self.valid_component_indicator.sum()),
            p=component_prob_t,          # sample da distribuição de modos
        )

    # PASSO D: Extrai o α normalizado do modo selecionado
    aranged = np.arange(len(data))
    normalized = normalized_values[aranged, selected_component].reshape([-1, 1])
    normalized = np.clip(normalized, -0.99, 0.99)   # garante range seguro

    # SAÍDA: [α, component_index]
    return np.stack([normalized[:, 0], selected_component], axis=1)

Passo a passo matemático

Fórmula de normalização

Para cada linha i, dado xᵢ:

Passo A — Normalização:
α(i,k) = (xᵢ - μₖ) / (4 × σₖ) para cada modo k

Passo B — Probabilidades:
p(i,k) = r(i,k) = [πₖ × N(xᵢ; μₖ, σₖ²)] / Σⱼ [πⱼ × N(xᵢ; μⱼ, σⱼ²)]

Passo C — Seleção:
kᵢ ~ Categorical(p(i,1), p(i,2), ..., p(i,K))
(NÃO é argmax — é amostragem estocástica)

Passo D — Extração:
αᵢ = α(i, kᵢ) αᵢ ∈ [-1, 1]

Saída: [αᵢ, kᵢ] (float64, 2 colunas)

Por que sample e não argmax? O artigo CTGAN é explícito (§4.2): a seleção probabilística adiciona estocasticidade que ajuda o GAN a aprender transições entre modos. Se um valor está na fronteira entre dois modos, às vezes será atribuído a um, vezes ao outro — isso cria uma "zona de sobreposição" que o gerador pode aprender.

# numerical.py:637-647
def _reverse_transform_helper(self, data):
    normalized = np.clip(data[:, 0], -1, 1)    # ← α seguro

    means = self._bgm_transformer.means_.reshape([-1])
    stds = np.sqrt(self._bgm_transformer.covariances_).reshape([-1])

    selected_component = data[:, 1].round().astype(int)
    selected_component = selected_component.clip(0, self.valid_component_indicator.sum() - 1)

    # FÓRMULA INVERSA: x = α × 4σ + μ
    std_t = stds[self.valid_component_indicator][selected_component]
    mean_t = means[self.valid_component_indicator][selected_component]
    reversed_data = normalized * self.STD_MULTIPLIER * std_t + mean_t

    return reversed_data
Fórmula de inversão

Entrada: [αᵢ, kᵢ] (α normalizado, modo selecionado)

Derivação:
α = (x - μₖ) / (4σₖ) → x = α × 4σₖ + μₖ

6. GaussianNormalizer — Cópula CDF + Normal Padrão

O GaussianNormalizer é uma abordagem alternativa baseada em cópulas estatísticas. A ideia: transformar qualquer distribuição em N(0,1) usando dois passos.

Princípio da cópula

Transformação:
1. x → u = F_dist(x) (CDF da distribuição ajustada → u ∈ [0,1])
2. u → z = Φ⁻¹(u) (inversa CDF da normal padrão → z ∈ ℝ)

Inversão:
1. z → u = Φ(z) (CDF da normal padrão → u ∈ [0,1])
2. u → x = F⁻¹_dist(u) (inversa CDF da distribuição → x ∈ ℝ)

# categorical.py:110-130
@staticmethod
def _compute_frequencies_intervals(categories, freq):
    frequencies = dict(zip(categories, freq))
    shift = np.cumsum(np.hstack([0, freq]))    # cumsum das frequências
    shift[-1] = 1                               # garante que termina em 1
    list_int = [[shift[i], shift[i + 1]] for i in range(len(shift) - 1)]
    intervals = dict(zip(categories, list_int))  # categoria → [início, fim]
    return frequencies, intervals

1 _transform_helper() — Construção do one-hot ▸ 
# categorical.py:705-723
def _transform_helper(self, data):
    coder = self._indexer                    # [0, 1, ..., N-1]
    codes = pd.Categorical(data, categories=self._uniques).codes

    rows = len(data)
    dummies = np.broadcast_to(coder, (rows, self._num_dummies))  # cada linha repete [0,1,...,N-1]
    coded = np.broadcast_to(codes, (self._num_dummies, rows)).T  # cada coluna repete o código da linha
    array = (coded == dummies).astype(int)                        # comparação elemento-a-elemento

    if self._dummy_na:
        null = np.zeros((rows, 1), dtype=int)
        null[pd.isna(data)] = 1
        array = np.append(array, null, axis=1)

    return array

12. LogitScaler e LogScaler — Transformações especializadas

LogitScaler

Para dados no range [0, 1] — aplica logit (transformação) e sigmoid (inversão).

# numerical.py:710-722
def _transform(self, data):
    data = self._transform_helper(data)
    data = np.clip(data, self._EPSILON, 1 - self._EPSILON)
    return logit(data)
    # logit(p) = ln(p / (1-p))

def _reverse_transform(self, data):
    return sigmoid(data)
    # sigmoid(x) = 1 / (1 + e^(-x))
Exemplo
x = 0.7
logit(0.7) = ln(0.7/0.3) = ln(2.333) = 0.847

Inversão:
sigmoid(0.847) = 1/(1+e⁻⁰·⁸⁴⁷) = 0.700

LogScaler

Aplica log na transformação e exp na inversão. Para dados positivos com range grande.

# numerical.py:748-768
def _transform(self, data):
    data = self._transform_helper(data)
    data = np.clip(data, self._EPSILON, None)
    return np.log(data)

def _reverse_transform(self, data):
    return np.exp(data)
Exemplo
x = 12450
log(12450) = 9.429

Inversão:
exp(9.429) = 12450.0

15. Por que 4σ e não 1σ? Análise detalhada

O CTGAN usa tanh como ativação final do gerador. A saída do tanh está sempre em [-1, 1].

Análise do range de cobertura

Com 1σ (z-score padrão):
P(−1 ≤ z ≤ 1) = erf(1/√2) = 0.6827 = 68.27%
→ 31.73% dos valores ficam FORA de [-1, 1]
→ tanh saturaria para esses valores (gradiente ≈ 0)
→ O gerador não conseguiria aprender

Com 4σ (usado pelo CTGAN):
P(−4 ≤ z ≤ 4) = erf(4/√2) = 0.99994 = 99.99%
→ Apenas 0.01% dos valores ficam fora de [-1, 1]
→ Quase todos os valores recebem gradientes úteis

Comparação visual:
1σ: [----========--------========----] 68% coberto
2σ: [--------============------------] 95% coberto
3σ: [------------================----] 99.7% coberto
4σ: [----------------================] 99.99% coberto ← CTGAN

A constante STD_MULTIPLIER = 4 está hardcoded em numerical.py:524. Não é configurável pelo usuário.

Impacto do clipping

Exemplo de clipping
Valor real: x = 100000 (outlier extremo)
Modo: μ = 38483, σ = 14912

α calculado = (100000 - 38483) / (4 × 14912) = 1.031
α após clip = 0.99

Inversão: x = 0.99 × 4 × 14912 + 38483 = 97535.7
Erro: 2.5% (muito bom para um outlier)

# base.py:364-375
def _set_seed(self, data):
    hash_value = self.columns[0]
    for _, row in data.head(5).iterrows():
        hash_value += str(row[self.columns[0]])

    hash_value = int(hashlib.sha256(hash_value.encode('utf-8')).hexdigest(), 16)
    self.random_seed = hash_value % ((2**32) - 1)
Exemplo de geração de semente

Coluna: "balance"
Primeiros 5 valores: 12450.0, 35800.0, -230.0, 0.0, 52000.0

hash_value = 0x7a3f... (256 bits)
random_seed = hash_value % (2³² − 1) = 2147483647

→ Esta semente é a mesma sempre que a mesma coluna é processada

O decorator @random_state

# base.py:42-58
@contextlib.contextmanager
def set_random_states(random_states, method_name, set_model_random_state):
    original_np_state = np.random.get_state()      # snapshot do estado global
    random_np_state = random_states[method_name]
    np.random.set_state(random_np_state.get_state()) # restaura estado do transformer
    try:
        yield
    finally:
        current_np_state = np.random.RandomState()
        current_np_state.set_state(np.random.get_state())
        set_model_random_state(current_np_state, method_name)
        np.random.set_state(original_np_state)      # restaura estado global

Isso é chamado 4 vezes por operação de transformação:

  1. fit() → @random_state
  2. transform() → @random_state
  3. reverse_transform() → @random_state
  4. Mais 1 para cada coluna no pipeline
